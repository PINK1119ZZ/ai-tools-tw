AI 電子發票與金流工具推薦 2026：綠界 ECPay vs TapPay vs 藍新 NewebPay — 台灣電商收款、發票自動化與對帳完整比較

📅 2026 年 11 月 14 日 ⏱️ 11 分鐘閱讀 👤 小凡

台灣電商最容易被低估的成本，不是廣告，而是收款與發票。一筆訂單從刷卡、撥款、開立電子發票、上傳財政部、退貨折讓到月底對帳，任何一個環節卡住，輕則客服被客訴淹沒，重則營業稅申報出錯被補稅。2026 年的金流平台已經不只是「能刷卡」：綠界 ECPay 把金流、物流、電子發票收進同一家公司、TapPay 用站內付把結帳轉換率拉到最高、藍新 NewebPay 則以老牌穩定性搭配 ezPay 發票，成為許多品牌的第二家備援金流。

本文從台灣電商、自架站、Shopify 賣家與訂閱制品牌的實際需求出發，比較三大平台的費率結構、發票整合方式、串接難度與選型情境。費率會隨產業、量體與合約議價變動，文中數字以各廠商官網 2026 年公告為基準，簽約前務必再向廠商取得書面報價確認。

一、為什麼 2026 年還要重新選金流與發票工具？

1. 電子發票已經不是加分項，是法規門檻

台灣 B2C 網路交易依法須開立電子發票並上傳財政部平台。手動開立在月訂單破百筆後就會失真：漏開、重開、折讓單沒跟上退貨，都是會計師最頭痛的對帳項目。能在「付款成功」當下自動開立、退款時自動作廢或折讓的金流，才是真正省下人力的工具。

2. 結帳頁跳轉直接吃掉轉換率

傳統第三方金流是導轉式結帳：消費者被帶到金流商的頁面輸入卡號，再跳回官網。實務上這段跳轉會流失一部分結帳意願，品牌官網的視覺也在最關鍵的一步被打斷。站內付（消費者不離開你的網站就完成付款）因此成為 2026 年轉換率優化的主戰場。

3. 單一金流是營運風險

金流商的系統維護、風控誤判或帳號審核問題，都可能讓整間店在促銷檔期收不到款。成熟的台灣電商通常會同時開通兩家金流互為備援，主金流出狀況時能在數小時內切換，而不是等客服回覆。

二、綠界 ECPay：金流、物流、發票一次搞定的一站式平台

綠界科技是台灣數位金流市場規模最大的業者之一，定位是第三方支付：賣家不必自己跟每家銀行簽約，由綠界代收再撥款。它最大的差異化是同一家公司同時提供金流、超商物流與電子發票，對沒有工程團隊的中小賣家來說，一個後台就能對完帳。

核心功能

  • 收款方式最完整：國內信用卡一次付清、分期、定期定額、Apple Pay、ATM 虛擬帳號、超商代碼與條碼、銀聯卡，特約賣家另可開通街口支付、iPASS MONEY 與無卡分期
  • 電子發票加值中心：B2C 與 B2B 發票皆可經 API 開立、作廢、折讓，提供 PHP、Python、C# SDK，也有離線版規格給網路不穩的 POS 場景
  • 超商物流整合：7-11、全家、萊爾富寄件與取貨付款在同一後台，訂單、收款、出貨狀態不用跨三個系統核對
  • 站內付 2.0：除了傳統導轉頁，也提供消費者留在商家頁面完成付款的方案，縮小與支付閘道的體驗差距
  • 開發文件成熟：ECPay Developers 文件、測試環境與各語言 SDK 齊全，WordPress、Shopify 等平台都有現成外掛

費率結構（2026 年官網公告，未稅）

  • 一般賣家：國內信用卡 2.75%、每筆最低 5 元，另收含稅 1 元訂單處理費；加 5% 營業稅後實際約 2.89%。無月費、年費
  • ATM 虛擬帳號：1%，每筆最低 15 元；超商代碼每筆 31 元、超商條碼每筆 16 元（皆未稅）
  • 特約賣家：國內信用卡可議至 1.85%–2.75% 區間，但需支付系統設定費 5,000 元與金流服務年費（1 年 13,000 元、2 年 22,100 元、3 年 27,300 元，皆未稅），費率依風險評估決定，不是申請就拿得到最低價
  • 撥款：款項於付款後約 10 日內撥入綠界帳戶，再依提領設定轉入銀行

適合誰、不適合誰

適合需要超商取貨付款、電子發票與金流由同一家處理的中小型電商，以及沒有專職工程師、希望用現成外掛上線的賣家。綜合評分 88／100。不適合極度在意結帳頁品牌體驗、或交易量已大到值得直接跟銀行談費率的品牌——前者看 TapPay，後者應評估支付閘道方案。

三、TapPay：站內付與轉換率優先的支付閘道

TapPay（Cherri Tech）的定位與綠界不同：它同時提供支付閘道與中小型商家的代收付服務。支付閘道模式下，款項由合作收單銀行直接撥付，TapPay 本身不經手資金，這對在意金流掌控權與對帳透明度的品牌是關鍵差異。

核心功能

  • 站內付體驗：信用卡欄位嵌在商家自己的結帳頁，消費者不離開官網，視覺與品牌一致，是三家之中結帳體驗最接近國際支付的一家
  • 一個 API 串多家收單行：閘道模式可串中國信託、玉山、台新、國泰世華、凱基等十餘家銀行與聯合信用卡中心，不用每家銀行各寫一支串接
  • 行動支付覆蓋完整：Apple Pay、Google Pay、LINE Pay、街口支付都能在同一套 API 下開啟
  • Cherri X 風險防護：內建風控系統，後台可看每筆交易的支付細節、做帳務調整與下載明細，並有二次驗證登入
  • iPhone 卡緊收：用 iPhone 就能接受感應支付，適合市集、快閃店與沒有刷卡機的線下場景
  • Shopify 官方串接：結帳介面貼近 Shopify 原生風格，個人戶與企業戶都可申請

費率與成本特性

  • 代收付方案由 TapPay 審核，收款可進任何台灣銀行帳戶；閘道方案則與指定收單銀行簽約，費率另議
  • 市場常見報價含一次性設定費與年費（約數千至萬元等級），實際數字以 TapPay 書面報價為準，不要沿用網路上的舊數字
  • 沒有內建物流與完整發票模組：電子發票需另接綠界、ezPay 或其他加值中心，物流也要另找解決方案

適合誰、不適合誰

適合有工程資源、把結帳轉換率當 KPI、願意用「金流一家、發票一家、物流一家」換取最佳支付體驗的品牌與 Shopify 賣家。綜合評分 84／100。不適合想一個窗口解決所有事情的小賣家——多管理兩到三個平台的行政成本，往往吃掉轉換率提升帶來的利潤。

四、藍新 NewebPay：老牌穩定與 ezPay 發票的組合

藍新金流（智冠集團）是台灣經營最久的第三方支付之一，服務超過 30 萬商戶，並同時具備第三方支付與電子支付雙重資格。它的電子發票產品線以 ezPay 品牌經營，簽約主體與金流不一定是同一家公司，這點在採購時要特別確認合約上的公司名稱。

核心功能

  • 收款管道完整：信用卡、ATM、超商代碼與條碼、行動支付與電子錢包，定期定額與信用卡分期都是標配
  • 智付通收款頁：沒有網站也能用收款頁或收款連結收錢，對課程販售、顧問服務、小量預購很實用
  • 捐款金流市佔領先：非營利組織與內容訂閱的捐款場景，藍新的支援深度是三家中最完整的
  • ezPay 電子發票整合：同集團發票服務可串接，開立、作廢、折讓流程與金流對帳可以打通
  • 系統穩定度口碑好：多年營運、雲端架構與多地備援，促銷檔期的穩定性是許多品牌選它當備援金流的原因

費率結構

  • 信用卡費率官網標示約 2.75% 起，依產業、量體與方案議價，沒有公開的固定月費或年費，以交易抽成為主
  • ATM、超商等非信用卡管道另有固定手續費，實際金額以簽約文件為準
  • 因為是「起」字而非固定數字，比較時一定要拿綠界與藍新的書面報價放在同一張表上算，不能只看官網

適合誰、不適合誰

適合已在使用 ezPay 發票、需要捐款或收款頁功能、以及想在綠界之外準備第二家備援金流的賣家。綜合評分 82／100。不適合主攻海外多幣別交易的品牌，跨境支援有限；交易量極低的個人賣家也要先算過撥款週期與最低成本是否划算。

七、三種實戰整合方案

方案一：綠界金流＋綠界發票＋綠界物流（中小電商標準配備）

訂單成立後由綠界收款，付款成功的 webhook 觸發同一家的發票 API 自動開立並寄送通知，出貨走超商物流回傳托運單號。整條鏈路在一個後台可查，月底用綠界報表對會計帳。適合月訂單數百到數千筆、沒有專職工程師的團隊。若要再自動化，可用 n8n 接 webhook，把發票號碼回寫到 Shopify 或 Google 試算表。

方案二：TapPay 站內付＋綠界發票（轉換率優先）

結帳頁用 TapPay 嵌入式卡號欄位，消費者全程留在官網；付款成功後由自建服務呼叫綠界電子發票 API 開立。這條路需要工程師維護 webhook 與錯誤重試，但結帳體驗最好。搭配 Shopify 使用時，記得發票與物流各有獨立對帳，不要假設一個後台能看到全部。

方案三：綠界主金流＋藍新備援（檔期風險控管）

日常交易走綠界，結帳頁保留「其他付款方式」導向藍新。主金流異常時，客服可以立刻改引導消費者走備援連結，而不是整站停收。兩家的發票都回寫到同一個訂單系統，會計只看訂單編號對帳，不看金流商後台。這個做法的成本是多一份合約與每月多一次對帳，但對單日營業額破十萬的檔期來說，停擺一小時的損失通常更大。

八、台灣電商常見的四個坑與解法

七之一、從申請到上線的實際流程

不管選哪一家，流程骨架都一樣，差別在每一步卡住的位置。先把這條路走一遍，比較時才知道自己缺的是文件、工程師還是時間。

第一步：備齊文件再送審

公司戶準備營利事業登記、負責人身分證、銀行存摺影本與網站網址；個人戶則是身分證、存摺與能證明實際販售的頁面（即使是社群或預購表單）。三家都會看販售內容是否涉及高風險品類，如票券、遊戲點數、生技保健，這類審核較久，甚至會被要求額外保證金。先在申請表如實填寫商品類別，比事後被要求補件省時間。

第二步：先接測試環境，不要直接碰正式金鑰

綠界與藍新都提供測試商店代號與測試信用卡號，TapPay 也有沙盒環境。把結帳頁先指向測試環境，跑完「成功、失敗、3D 驗證取消、重複通知、部分退款」五條路徑，再申請正式金鑰。正式金鑰與測試金鑰分開存放，不要寫進程式碼，放在環境變數或主機的秘密管理裡。

第三步：webhook 要能重送、要能對帳

金流商的付款通知可能遲到、重送或亂序。接收端要做三件事：用金流商提供的檢查碼驗證通知真的來自對方、以交易序號做冪等處理（同一筆通知來兩次只入帳一次）、處理失敗時回傳非成功狀態讓對方重送。發票開立放在「入帳成功」之後，而不是放在「收到通知」當下，避免通知重送導致重複開票。

第四步：上線後的每週對帳節奏

每週固定一天下載三份資料：金流商交易明細、發票平台開立紀錄、訂單系統的付款狀態。用訂單編號把三者串起來，差異超過零就要當天查，不要累積到月底。常見差異來源是跨日交易（晚上十一點付款、隔日才通知）、部分退款只退了錢沒開折讓、以及測試單混進正式報表。

八、台灣電商常見的四個坑與解法

1. 只看費率百分比，沒算固定費用與稅

綠界一般賣家的 2.75% 是未稅價，加營業稅後約 2.89%，信用卡還有每筆 1 元處理費；特約方案的年費要攤進每月交易量才知道實際成本。正確算法是拿過去三個月的真實訂單明細，逐筆套兩家的費率與最低收費，再加年費攤提，得出「每百萬交易的總成本」再比較。

2. 發票與金流不同步，退貨變孤兒折讓單

付款成功開了發票，但退款流程走人工，折讓單常常漏開。解法是把「退款」也做成事件：金流退款 webhook 一到，自動呼叫發票 API 作廢或開折讓，失敗則進重試佇列並通知會計，而不是靠月底人工翻訂單。

3. 測試環境沒測完就上線

三家都有測試環境，但很多賣家只測「付款成功」一條路。至少要測：付款失敗、3D 驗證中斷、重複通知（webhook 重送）、部分退款、發票開立失敗後的補開。這些邊界案例佔客服工單的大部分。

4. 個資與卡號合規被忽略

站內付看起來是卡號經過你的網站，實際上合規做法是用金流商的嵌入式欄位，卡號直接送到金流商，你的伺服器不碰卡號，才能避開 PCI DSS 的重負擔。自建結帳頁前記得確認串接方式屬於「不經手卡號」的類型，並用加密連線與最小權限的 API 金鑰。

十一、發票自動化的五個實務細節

金流選完只解決一半，電子發票才是每月固定消耗會計時間的地方。以下五點是台灣賣家最常在上線後才補做的設定，提前處理能少掉大半客服工單。

1. 載具、捐贈與紙本三條路都要測

結帳頁至少要給消費者三種選擇：手機條碼載具、愛心碼捐贈、以及公司戶統編。很多人只測統編，結果手機條碼格式驗證沒做，消費者輸入錯誤條碼後發票開到會員載具，月底才來客訴。條碼格式（斜線開頭加七碼）在前端就驗證掉，比事後重開發票便宜。

2. 開立時點要跟付款狀態綁定

貨到付款與超商取貨付款的發票，不該在訂單成立時開立，而該在取貨完成、款項確認後開立，否則退貨率高的品類會累積大量要作廢的發票。信用卡與 ATM 則可以在付款成功當下開立。把「開立時點」做成依付款方式分支的規則，而不是全站統一。

3. 折讓單比作廢單更常見

發票上傳財政部後超過時限就不能作廢，只能開折讓單。部分退款、折扣補差額、商品換貨都走折讓。自動化流程要能處理「一張發票對多張折讓單」，並把折讓單號回寫訂單，否則會計師在申報時對不到。

4. B2B 與 B2C 分開看

綠界的發票 API 把 B2B 與 B2C 分成兩套規格，買方是公司且需要交換發票的場景走 B2B，一般消費者走 B2C。賣給企業客戶的品牌不要用 B2C 的統編欄位硬湊，否則對方無法把發票納入進項扣抵，往來幾次就會要求你換金流。

5. 保留發票字軌與配號的緩衝

字軌每期申請一次，檔期爆量時配號用完會開不出發票，結帳流程直接中斷。在後台設定低水位告警，剩餘配號低於預估一週用量時就申請增額，不要等開立失敗的通知跳出來。

十二、三個月遷移計畫：從單一金流走向主備架構

已經在用某一家、想加開第二家的賣家，不需要一次切換。比較穩的節奏是三個月。

  • 第一個月：第二家只開測試環境，用歷史訂單重放付款、退款、發票三條流程，確認訂單編號能貫穿兩個系統。這段不影響正式營收。
  • 第二個月：正式環境上線，但只導 10% 的結帳流量過去，每天對一次帳，看費率、撥款天數與失敗率的實際數字，而不是用報價單想像。
  • 第三個月：依數據決定誰當主金流。轉換率差超過 5% 就讓站內付當主；行政成本差更大就讓一站式當主。另一家保留為備援，結帳頁留一個「其他付款方式」入口，並寫進客服的應變腳本。

遷移期間最容易漏的是定期定額。訂閱制商品的委託扣款綁在原金流商，不能只改結帳頁就以為搬完了，既有訂閱戶要逐批重新授權或維持在原金流直到合約到期。這部分建議搭配 訂閱管理工具 一起規劃，避免搬金流時把續訂弄斷。

十、常見問題 FAQ

綠界和藍新功能差不多，到底差在哪？

收款功能確實高度重疊，差異在三件事：發票是不是同一家公司（綠界是自家，藍新是同集團 ezPay、簽約主體分開）、你的開店平台外掛哪家維護較積極、以及書面報價後的實際費率。建議兩家都申請，用自己的交易明細試算，而不是看網友評價決定。

個人賣家可以申請嗎？

三家都接受個人戶與公司戶，但審核標準、可開通的付款方式與費率不同。個人戶通常無法拿到特約費率，也未必能開通全部行動支付。準備文件時把身分證、銀行存摺與營業事實（即使是個人）一次備齊，能縮短審核往返。

已經用綠界發票，可以只換金流嗎？

可以。發票與金流是兩條 API，TapPay 或藍新收款成功後，一樣能呼叫綠界發票 API 開立。要注意的是對帳鍵：用訂單編號貫穿金流交易序號與發票號碼，否則月底會對不出來。

站內付會不會讓我碰到信用卡資料、要過 PCI 認證？

用金流商提供的嵌入式欄位時，卡號直接送往金流商，你的伺服器不接觸卡號，合規負擔最低。不要自己做一個表單把卡號傳到自己的後端再轉送，那會落入最嚴格的合規範圍。串接前跟金流商確認所用方案的合規等級。

多久能上線？

用現成外掛（Shopify、WordPress）加綠界或藍新，文件齊全的話一週內可完成測試上線。TapPay 閘道方案因為要逐一與收單銀行簽約，時程通常以月計。無論哪家，都把測試環境的失敗案例跑完再切正式環境。

結論：先看你缺的是「少一個窗口」還是「高轉換率」

三家沒有絕對贏家。綠界 ECPay（88 分）適合想把金流、物流、發票交給同一家、用最低行政成本上線的中小電商；TapPay（84 分）適合有工程資源、把結帳轉換率放在第一位的品牌；藍新 NewebPay（82 分）適合已用 ezPay、需要收款頁或捐款功能、以及想要第二家備援的賣家。

實務上最穩的做法是：主金流選一家、備援開一家、發票固定一家，再用自動化把退款與折讓接起來。費率用自己的交易明細算，不看廣告頁上的數字。延伸閱讀可參考 AI 會計記帳工具比較、訂閱制電商工具比較與 電商物流工具比較，把收款之後的帳務與出貨也一併想清楚。
