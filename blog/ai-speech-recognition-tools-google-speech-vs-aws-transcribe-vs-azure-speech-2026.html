🔬 Google Speech-to-Text v2 深度評測

Google Cloud Speech-to-Text v2 GCP 原生 最低延遲

Google 於 2024 年推出的 Chirp 2 模型是目前繁體中文辨識準確率最高的商業 API 之一，底層採用 Universal Speech Model（USM）架構，在台灣普通話、帶有閩南語腔調的國語上表現尤為突出。

核心功能亮點

  • Chirp 2（USM）模型：超過 300 種語言，繁體中文字元錯誤率（CER）業界最低，連口音、快速語速都能應對
  • 即時串流（Streaming Recognize）：WebSocket 長連接，延遲低至 200-300ms，適合電話客服即時輔助
  • 多聲道轉錄：最多 2 聲道分離辨識，適合電話錄音（客戶 vs 客服）
  • 語音活動偵測（VAD）：自動偵測靜音段、截斷不必要的音訊，省費用
  • 說話者分離（Diarization）：最多 5 位說話者標記，輸出 SPEAKER_0/1/2 標籤
  • 詞彙適應（Phrase Hints / Adaptation）：注入產品名、專有名詞提升辨識率
  • 自動標點與數字格式化：「三千五百塊」自動轉為「3,500 元」
  • 台灣節點 asia-east1：在彰化，網路延遲比東京節點省 20-40ms

🔬 AWS Transcribe 深度評測

Amazon Transcribe 大批量最強 AWS 生態

AWS Transcribe 是三大平台中最適合大批量異步轉錄場景的選擇，搭配 S3 + Lambda 的 Serverless 架構可以做到幾乎零成本的自動擴展，非常適合需要每天處理數千小時音訊的企業。

核心功能亮點

  • Batch Transcription（異步）：丟 S3 檔案，拿 JSON 結果，支援 MP3/MP4/WAV/FLAC/OGG，最多 4 小時音訊
  • Streaming Transcription：HTTP/2 或 WebSocket，支援繁體中文（zh-TW）即時串流
  • 說話者分離：最多 10 位說話者，三大平台中最多
  • Automatic Content Redaction：自動遮蔽 PII（個人識別資訊），如電話號碼、身分證、地址，特別適合金融/醫療合規需求
  • Custom Vocabulary：上傳特定詞彙表提升辨識率，支援發音提示（SoundsLike）
  • Custom Language Model（CLM）：用自有文字語料微調語言模型，適合專業領域（醫療/法律/金融）
  • Transcribe Medical：獨立的醫療專屬模型，支援醫療術語（英文為主，中文有限）
  • Call Analytics：結合情感分析、對話段落分類、中斷偵測，適合客服品保
  • Subtitles 自動輸出：直接產出 SRT/VTT 字幕檔，影片製作流程大省時

  • Transcribe Medical：$0.075/分鐘
  • Call Analytics：$0.0016/秒（含情感分析）
  • 每月免費：60 分鐘（Free Tier，前 12 個月）

✅ 優點

  • 批量異步轉錄性價比最高
  • 說話者分離最多（10 人）
  • PII 自動遮蔽（合規利器）
  • CLM 客製化語言模型完整

  • 介面與設定複雜度高
  • Call Analytics 費率偏貴

🔬 Azure Speech Service 深度評測

Azure AI Speech Service 領域微調最強 台語有限支援

Azure Speech Service 是三大平台中客製化能力最完整的選擇，Custom Speech 功能讓企業可以上傳自有音訊+轉錄資料訓練專屬模型，大幅提升特定領域（醫療問診、法庭記錄、金融電話）的辨識準確率。另外，Azure 是三大平台中唯一提供台語（閩南語）TTS 語音的服務（STT 端台語支援仍有限）。

核心功能亮點

  • Custom Speech：上傳音訊+逐字稿，以自有資料微調 STT 模型，適合醫療術語、法律條文、產業黑話
  • Real-time Transcription（即時轉錄）：WebSocket 連接，支援連續辨識，內建降噪前處理
  • Batch Transcription：透過 REST API 非同步處理，支援 Azure Blob Storage 整合
  • Meeting Transcription（Teams 整合）：可直接接入 Microsoft Teams 會議，自動輸出逐字稿+說話者標記
  • Pronunciation Assessment：評分發音準確度、流暢度、韻律，適合語言學習 App
  • 說話者分離（Diarization）：最多 6 人，輸出 Guest-1/Guest-2 標籤
  • 台語 TTS 語音：zh-TW-HokkienTaiwaneseMale 神經語音（TTS 端），STT 端台語辨識仍 beta
  • 語言偵測：可同時辨識多語言混合輸入（如中英夾雜的台灣對話）
  • Microsoft 365 深度整合：Word 即時聽寫、PowerPoint Subtitles、Teams 字幕
  • 免費層每月 5 小時：三大平台中最高的免費額度

🎯 台灣 6 大使用場景完整建議

🎧 場景 1：電話客服中心即時輔助（Real-time Agent Assist）

推薦：Google Speech-to-Text v2

客服座位需要即時在螢幕上顯示客戶說話的文字，輔助座席快速回應。Google 的 Chirp 2 在繁體中文上準確率最高，且即時串流延遲低至 200-300ms，可搭配 Dialogflow CX 或自建 NLU。如果已用 Genesys / Avaya + AWS 生態，改用 AWS Transcribe Streaming + Call Analytics 的整合成本較低。

💡 台灣實務提醒：電話音訊通常是 8kHz 單聲道 G.711，三家都支援，但建議啟用 2 聲道分離（客戶/客服各一軌）以提升準確率。

📋 場景 2：視訊會議自動轉錄（Zoom / Teams / Google Meet）

推薦：Azure Speech Service（Teams 用戶）/ Google（Meet 用戶）

使用 Microsoft Teams 的企業可以透過 Azure Cognitive Services + Teams Bot Framework 直接接入會議轉錄，說話者分離最多 6 人，輸出 DOCX 格式逐字稿。Google Meet 用戶則建議呼叫 Google Speech API 搭配 Meeting Recordings GCS 管道。

💡 台灣實務提醒：會議中常有中英夾雜（如「我們的 roadmap 是這樣...」），Azure 的自動語言偵測在這個場景最穩。

🎬 場景 3：影片自動上字幕（YouTube / TikTok / 線上課程）

推薦：AWS Transcribe（大批量）/ Azure（特定領域課程）

AWS Transcribe 可以直接輸出 SRT/VTT 字幕檔，搭配 S3 + Lambda 做到全自動化的「上傳影片 → 產出字幕 → 推播 CDN」管道，批量定價最低（≈ NT$44/小時）。如果是醫療或法律課程，建議用 Azure Custom Speech 先微調模型，準確率可提升 30-50%。

💡 台灣實務提醒：Hahow、TutorABC、PressPlay 等平台都有字幕需求，用 AWS Transcribe 批量處理 MP4 課程影片是最省錢的選擇。

🏥 場景 4：醫療問診錄音轉電子病歷（EMR）

推薦：Azure Speech Service（Custom Speech）

醫療場景對準確率要求極高，「阿莫西林」被辨識成「阿模細菌」可能造成醫療事故。Azure Custom Speech 支援上傳醫療音訊+逐字稿訓練，搭配自訂詞彙表（ICD-10 代碼、藥品名稱、解剖術語），準確率可達 96%+。另需注意台灣的《醫療機構電子病歷製作及管理辦法》對資料存放地點的規定，Azure 的 Taiwan North 計畫中，現階段建議用 East Asia（香港）或確認 HIPAA/HITECH 合規。

💡 台灣實務提醒：AWS Transcribe Medical 主要針對英文醫療術語，中文醫療場景目前 Azure Custom Speech 勝出。

📖 場景 5：語言學習 App（發音評分）

推薦：Azure Speech Service（Pronunciation Assessment）

Azure 獨家的 Pronunciation Assessment API 可以評分準確度（Accuracy）、流暢度（Fluency）、完整度（Completeness）、韻律（Prosody），返回音素（Phoneme）層級的詳細評分，是開發英語/普通話學習 App 的最佳選擇。Google 和 AWS 無此功能。

💡 台灣應用案例：適合「TutorABC 模式」的口說練習功能，或搭配 Hahow 課程做作業評分系統。

🏠 場景 6：IoT 語音控制 / 智慧家庭（Edge + Cloud 混合）

推薦：Google Speech-to-Text（低延遲優先）/ Azure（邊緣部署）

智慧音箱、工廠語音控制等 IoT 場景需要低延遲。Google 的 Streaming API 延遲最低，適合雲端即時模式。Azure 則提供 Speech SDK 的 Edge 部署版（Docker 容器），可在無網路環境下本地執行辨識，適合工廠環境或隱私敏感設備。AWS IoT 生態用戶可選 Transcribe Streaming + Lambda@Edge。

💡 台灣實務提醒：台灣智慧家庭市場以國語為主，三家繁體中文辨識率都能接受，但如果有台語「阿嬤指令」需求，目前三家都還做不到理想效果。

🔍 台灣特別注意事項

繁體中文 vs 簡體中文

三大平台都支援 zh-TW（繁體台灣中文），但底層語料仍以 zh（普通話）為主，繁體字輸出主要靠後處理轉換。Google Chirp 2 在繁體字詞彙辨識（如「資訊」而非「信息」、「軟體」而非「軟件」）上表現最好。

台語（閩南語）現況

截至 2026 年，三大國際平台對台語的 STT 支援都非常有限。Azure 有 zh-TW-HokkienTaiwaneseMale 神經語音（TTS 端），但 STT 台語辨識仍在 beta 階段且準確率不穩定。如果台語辨識是核心需求，建議考慮國內方案如 NTUT（北科大）的台語 AI 研究專案，或搭配在地 ASR 廠商（如意傳科技、訊連科技的 VOICEPASS）。

個人資料保護法（PDPA）合規

台灣《個人資料保護法》要求語音資料的跨境傳輸需要當事人同意或符合相關豁免條件。三家平台的資料處理地點：

  • Google：可指定 asia-east1（台灣彰化），資料不出台灣
  • AWS：最近節點為東京，資料過境日本
  • Azure：East Asia 節點在香港，Taiwan North 尚在規劃

若處理醫療、金融等敏感語音資料，優先選擇 Google asia-east1 節點或確認 Data Processing Agreement（DPA）。

發票與稅務

三大平台在台灣消費均需繳納 5% 營業稅。Google Cloud 和 Microsoft Azure 均可申請統一發票；AWS 台灣消費者需透過 AWS Inc. 帳單，報稅時需自行列計境外數位服務稅。

🤔 8 大常見問題（FAQ）

Q1：繁體中文辨識率到底差多少？有實際數據嗎？

根據第三方評測（Kaldi / OpenSLR 測試集），2026 年的參考數據：Google Chirp 2 繁體中文 CER（字元錯誤率）約 3-5%，Azure STT 約 5-8%（Custom Speech 微調後可降至 3-4%），AWS Transcribe 約 6-9%。但注意：這些是乾淨實驗室音訊的數據，真實電話語音（8kHz、背景雜訊、口音）會讓誤差率提高 2-3 倍。

Q2：我用 LINE 客服，哪個 STT API 最容易整合？

LINE 語音訊息（.m4a 格式）可以下載後丟給任何一家 API 做非同步轉錄。推薦流程：LINE Webhook → AWS Lambda 接收 → 下載音訊 → 呼叫 AWS Transcribe → 儲存結果 → 觸發後續邏輯。全部在 AWS 生態內最省網路傳輸費。如果已用 GCP，換成 Cloud Functions + Google STT 也行。

Q3：要轉錄舊的電話錄音檔（幾千小時），哪家最省錢？

AWS Transcribe 批量異步轉錄性價比最高（≈ NT$44/小時），且可搭配 S3 Intelligent-Tiering 存音訊降低儲存成本。如果量大到每月超過 100 萬分鐘，三家都提供企業協議折扣，建議洽詢業代拿 Committed Use Discount。

Q4：可以用開源的 Whisper 代替嗎？

OpenAI Whisper（或 faster-whisper）在繁體中文上表現優秀，large-v3 模型 CER 可與 Google Chirp 2 相當，而且完全免費（自架成本）。缺點是：即時串流需要自建管線（latency 較高）、需要 GPU 伺服器（DigitalOcean GPU Droplet 或 Lambda Labs），適合技術團隊、不想依賴雲端廠商的用戶。如果你有技術能力，Whisper 是很好的起點。

Q5：Azure Custom Speech 要準備多少訓練資料？

微軟建議最少 30 分鐘的相關音訊 + 對應逐字稿即可開始微調，但要有明顯提升效果建議 1-5 小時。特別提醒：訓練資料的音質和逐字稿準確度比量更重要，一份噪雜音訊 + 錯誤逐字稿反而會讓模型變差。

Q6：三家 API 支援哪些輸入音訊格式？

Google STT：LINEAR16/MULAW/ALAW/MP3/OPUS/FLAC/WEBM/OGG；AWS Transcribe：MP3/MP4/WAV/FLAC/AMR/OGG/WebM（Batch），PCM/OGG/FLAC（Streaming）；Azure Speech：WAV/MP3/OGG/FLAC/AIFF/WMA/AAC/AMR。三家都支援主流格式，差異不大。

Q7：我的產品在台灣做，但打算拓展到日本、新加坡，哪家多語言支援最好？

Google Chirp 2 支援 300+ 語言最全面，日語、粵語、馬來語都支援良好；Azure 支援 130+ 語言，日語表現優秀；AWS 支援 90+ 語言，日語（ja-JP）評測良好。如果東南亞市場重要，Google 的多語言覆蓋最廣。

Q8：用 AI 語音辨識一定要有程式開發能力嗎？

不一定。以下是無程式碼 / 低程式碼選項：1) Google Cloud Console 有線上試用介面可以直接上傳音訊測試；2) Azure Speech Studio 提供圖形化介面訓練 Custom Speech；3) n8n / Make 等自動化平台有內建 AWS Transcribe / Google STT 節點，拖拉就能串接；4) Microsoft Power Automate 可串接 Azure Speech 做 Teams 會議轉錄，完全無程式碼。
